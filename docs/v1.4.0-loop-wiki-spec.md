# v1.4.0 Loop & Wiki — Design Specification

**版本**: v1.4.0
**代号**: Loop & Wiki
**日期**: 2026-06-29
**状态**: 实现中
**基线**: v1.3.2 Gate

> **Slogan**: Loops persist. Wiki remembers. Chaos resumes.

---

## 1. 设计动机

v1.3.2 的 Gate 状态机解决了"硬约束"，但暴露了三个深层问题：

1. **响应式而非自驱** — hooks 只在工具调用时触发，没有"主动复盘"
2. **记忆扁平** — 6 个 CSV + 多个 jsonl，没有可寻址、可链接、可演化的长期记忆
3. **断点丢失** — 会话中断后无法精准恢复到 task 粒度

v1.4.0 引入两个思想：

- **Loop Engineering (Karpathy)**: 把 prompt 升级为 loop，四件套 state/policy/environment/memory
- **Project Wiki (Karpathy)**: 给 agent 一个可寻址、可链接、可演化的 wiki，而非 scratchpad

## 3. Epic 1 — Loop Engine

### 3.1 四帧循环

每次完整的 agent 行为被记录为四个 frame：

| Frame | 何时写入 | 写入者 | 包含 |
|-------|---------|--------|------|
| `observe` | PreToolUse | hook | 当前工具名 + 输入摘要 + 时间戳 |
| `decide` | PreToolUse | hook | Gate 检查结果 + cursor 状态 |
| `act` | PostToolUse | hook | 工具退出码 + 输出长度 |
| `reflect` | Stop | hook | LP 检测结果 + 下一步建议 |

### 3.2 Cursor 协议

`.chaos-harness/loop/cursor.json`：

```json
{
  "session_id": "uuid",
  "version": "1.4.0",
  "started_at": "ISO8601",
  "last_frame": "act|observe|decide|reflect",
  "last_frame_at": "ISO8601",
  "tick": 1234,
  "current_task": {
    "id": "task#7",
    "subject": "...",
    "stage": "W08_development"
  },
  "open_loops": [
    {"id": "loop-001", "topic": "...", "blocked_by": null}
  ]
}
```

**原子写入**：先写 `cursor.json.tmp.<pid>`，`fs.renameSync()` 替换。Windows + POSIX 均原子。

### 3.3 Journal 协议

`.chaos-harness/loop/journal.jsonl` 每行一个 frame：

```json
{"ts":"2026-06-29T10:00:00Z","tick":1234,"frame":"observe","tool":"Write","input":{"file_path":"..."},"hash":"sha256:..."}
```

journal 永不修改，只追加。每 100 帧滚动一次到 `journal.<date>.jsonl`。

### 3.4 Inbox / Outbox

- `inbox.jsonl`：外部输入队列（用户指令、调度任务）
- `outbox.jsonl`：待向用户输出的复盘信息

由 SessionStart hook 消费 outbox 中堆积的复盘消息。

## 4. Epic 2 — Project Wiki

### 4.1 目录结构

```
.chaos-harness/wiki/
├── index.md              # 自动生成的总目录
├── patterns/             # 模式（代码模式、Gate 模式、UI 模式）
│   ├── pat-001-xxx.md
│   └── ...
├── decisions/            # 关键决策（ADR-style）
│   ├── dec-001-xxx.md
│   └── ...
├── incidents/            # 事故/反模式
│   ├── inc-001-xxx.md
│   └── ...
└── sessions/             # 每次会话快照
    ├── last.md           # 最后一次会话（用于 resume）
    └── 2026-06-29-xxx.md
```

### 4.2 Frontmatter Schema

每个 wiki .md 必须有：

```yaml
---
id: pat-001                          # 短 id，全 wiki 唯一
type: pattern|decision|incident|session
title: "..."                         # 可读标题
tags: [gate, java, springboot]       # 标签
links: [pat-002, dec-005]            # 双向链接（另一端由 indexer 自动维护）
sources:                             # 数据来源
  - observations.jsonl#L1234
  - intent-log.jsonl#L5678
created: 2026-06-29T10:00:00Z
updated: 2026-06-29T10:00:00Z
confidence: 0.85                     # 0-1，indexer 用于排序
status: draft|promoted|archived
---
```

### 4.3 三层晋升

```
observations.jsonl  (raw)
     │  ≥3 次同质观察 + indexer 聚类
     ▼
patterns/           (promoted)
     │  ≥5 次复用 + 用户确认
     ▼
iron-law-rules.csv  (canonical)
```

### 4.4 索引器 (`wiki-indexer.mjs`)

每次 PostToolUse 异步触发：
1. 扫描 wiki 所有 .md，提取 frontmatter
2. 写入 `index.md`（按 type 分组的清单）
3. 检查 `links` 字段，双向链接缺失时自动在另一端补齐
4. 给每个文件计算 `lastIndexed` 哈希，避免重复扫描

### 4.5 搜索 (`wiki-search.mjs`)

复用现有 BM25 引擎（`search.py`），把 wiki 全文加入语料库：

```bash
node scripts/dev-intelligence.mjs --query "xxx"
# 输出：
# [CSV]    gate-patterns.csv:L12  (score: 8.5)
# [Wiki]   patterns/pat-007.md    (score: 7.2)  ← 新增
# [Wiki]   decisions/dec-003.md   (score: 6.1)
```

## 5. Epic 3 — Resume Engine

### 5.1 三层快照

| 层 | 来源 | 写入时机 |
|----|------|----------|
| L1 Gate | `.chaos-harness/gates/*.json` | Gate 通过/失败时 |
| L2 Loop | `.chaos-harness/loop/cursor.json` | 每个 frame 后 |
| L3 Session | `wiki/sessions/<id>.md` | Stop hook |

### 5.2 Session Snapshot 格式

```yaml
---
id: ses-2026-06-29-1023
type: session
title: "v1.4.0 Epic 1 Loop Engine implementation"
tags: [v1.4.0, loop, in-progress]
links: [pat-001, dec-002]
created: 2026-06-29T10:00:00Z
status: in-progress | completed | interrupted
---

## Progress

- [x] task#1 P0 git init
- [x] task#2 P1 design spec
- [ ] task#3 P2 install rebuild
- ...

## Decisions (this session)

- 采用四帧循环代替三帧 (decide → see dec-002)
- Wiki frontmatter 必填字段定为 7 个

## Open loops

- inbox#42: 还未处理的用户问题
- gate-w08 验证失败待修复

## Resume hints

下次启动时：
- 从 task#3 P2 继续
- 检查 gate-w08 修复进度
```

### 5.3 SessionStart 自动恢复

`scripts/session-start.mjs` 启动时：
1. 读 `wiki/sessions/last.md`
2. 如果 `status: in-progress` 或 `interrupted`：
   - 输出 "🔄 Resume from session ses-xxx" 提示
   - 列出未完成 task 与 open loops
   - 打印 resume hints
3. 否则正常启动

## 6. Epic 4 — Skill & Hook 瘦身

### 6.1 Skill 合并方案

| 删除/合并的 Skill | 接收方 | 理由 |
|------------------|--------|------|
| `gate-intelligence-check`（已删，作为 Gate）| `dev-intelligence` | 同源能力 |
| `hooks-manager` | `gate-manager` | hook 是 Gate 的一部分 |
| `project-scanner` | `harness-generator` | 扫描是生成的前置 |
| `overview` | 保留 | 入口 |
| `overdrive` | 保留 | 应急模式 |
| `iron-law-enforcer` | 保留 | 核心 |
| `version-locker` | 保留 | IL001 |
| `project-state` | 改名 `resume`，融入 Resume Engine | - |
| `product-manager` | 保留 | 可选 |
| `java-checkstyle` | 保留 | 可选 |
| `ui-generator` | 保留 | 可选 |
| `web-access` | 保留 | 可选 |
| `gate-manager` | 保留（吃 hooks-manager） | 核心 |
| `dev-intelligence` | 保留（吃 wiki-search） | 核心 |
| `harness-generator` | 保留（吃 project-scanner） | 核心 |

**v1.4.0 Skill 最终数量：12 个**（核心 8 + 可选 4）

```
core: overview, overdrive, iron-law-enforcer, version-locker, resume,
      gate-manager, dev-intelligence, harness-generator
optional: product-manager, java-checkstyle, ui-generator, web-access
```

### 6.2 Hook 重构

PostToolUse 当前 4 个独立 hook：
- learning-update.mjs
- project-pattern-writer.mjs
- workflow-track.mjs
- instinct-collector.mjs

合并为 **`post-write-dispatcher.mjs`**：
- 并发触发上述 4 个
- 同文件 5 秒 debounce
- 总耗时控制在 500ms 内（异步触发，不阻塞）

## 7. Epic 5 — Cross-Platform 安装

### 7.1 痛点

1. **Git 二进制定位**：Windows 下 git 在 `C:\Program Files\Git\bin\` 含空格
2. **路径分隔符**：Git Bash `/c/...` vs cmd `C:\...` 差异
3. **中文/特殊字符**：`万物入侵` 等路径在 child_process.execSync 时乱码

### 7.2 install.mjs 统一入口

```bash
# install.bat / install.sh 改为单行调用
node "%~dp0scripts\install.mjs"
node "$(dirname "$0")/scripts/install.mjs"
```

`install.mjs` 流程：
1. 调用 `path-sanity.mjs` 检查安装路径合规性
2. 调用 `git-detector.mjs` 定位 git
3. 写入 `.chaos-harness/config.json` 记录解析结果
4. 创建必要的 wiki/loop 目录
5. 运行自检（self-test 子集）

### 7.3 git-detector.mjs 探测顺序

```
1. which git / where git    (PATH 中)
2. C:\Program Files\Git\bin\git.exe
3. C:\Program Files (x86)\Git\bin\git.exe
4. %USERPROFILE%\scoop\apps\git\current\bin\git.exe
5. %ProgramData%\chocolatey\bin\git.exe
6. wsl which git           (WSL 兜底)
```

找到后写入 `.chaos-harness/config.json`：

```json
{
  "git": {
    "binary": "C:\\Program Files\\Git\\bin\\git.exe",
    "version": "2.37.0",
    "detected_via": "program-files"
  }
}
```

### 7.4 path-sanity.mjs 检查规则

| 规则 | 严重程度 | 说明 |
|------|---------|------|
| 含空格 | warning | 提示，但允许（用引号包裹） |
| 含中文/非 ASCII | error | 拒绝，给出明确错误 |
| 路径长度 > 200 | warning | Windows MAX_PATH 风险 |
| 路径以 `~` 开头 | error | 未展开 |

## 8. 验收标准

| Epic | 验收项 | 通过标准 |
|------|--------|---------|
| 1 | Loop persistence | 模拟 SIGKILL 后 cursor.json 完好可解析 |
| 1 | Journal append-only | 1000 帧后 journal 完整无损 |
| 2 | Wiki indexer | 创建 5 个 pattern，自动生成 index.md，双向链接补全 |
| 2 | Wiki search | dev-intelligence --query 能命中 wiki 条目 |
| 3 | Resume | 中断 3 步任务的第 2 步，重启后 SessionStart 提示从第 3 步继续 |
| 4 | Skill 数量 | skills/ 目录有且仅有 12 个目录 |
| 4 | Hook 性能 | PostToolUse 总耗时 < 500ms |
| 5 | 跨平台安装 | `D:\code\` 和 `C:\Program Files\test\` 两种路径均成功 |
| 5 | 中文路径拒绝 | 路径含中文时 install.mjs 拒绝并给出明确错误 |
| Self-Test | 全量通过 | 包括新模块，0 失败 |
